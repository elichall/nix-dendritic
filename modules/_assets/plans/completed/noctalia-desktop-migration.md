# Noctalia Desktop Migration — 3-Host Split Plan

## 1. Context & Goal

The current `workstation.nix` host is a heavily customized Hyprland desktop with
hand-rolled components: custom waybar config, theme engine with GTK CSS
generation, otter-launcher, showoff sleep screen, awww wallpaper daemon, and
waypaper integration. This works but demands significant maintenance bandwidth
that could go to actual development work.

**Goal:** Split into three hosts and adopt Noctalia Shell as the desktop base,
reducing system management overhead while keeping the developer toolchain
intact.

---

## 2. Research Findings

### 2.1 Noctalia Shell v5

**What it is:** A native Wayland desktop shell — bars, launcher, notifications,
lock screen, wallpaper, dock, control center, OSD, clipboard history, desktop
widgets, and theming. Built directly on Wayland + OpenGL ES (no Qt/GTK
dependency). v5 is a complete rewrite from the Quickshell-based v4.

**Key facts:**
- 9.6k GitHub stars, MIT license, actively maintained (5,300+ commits)
- **v5 is currently in Beta** — core features stabilizing, occasional config
  adjustments expected
- Hyprland is a first-class supported compositor
- NixOS flake input with Home Manager module, NixOS module, and binary cache
  (Cachix)
- TOML configuration with hot reload
- Theming system: palette generation (Material You via matugen), app theming
  (GTK + Qt templates), built-in theme presets
- Plugin system for extensions
- Required NixOS options: NetworkManager, Bluetooth, UPower, power-profiles-daemon

**What it replaces in our setup:**

| Current Component | Noctalia Equivalent | Notes |
|---|---|---|
| waybar (373-line config) | Noctalia bar + widgets | Battery, bluetooth, network, media, clock, workspaces, tray — all built-in |
| otter-launcher | Noctalia launcher | **User wants to keep otter** — Noctalia launcher can coexist |
| waypaper | Noctalia wallpaper picker | Built-in wallpaper widget + backdrop |
| awww (wallpaper daemon) | Noctalia wallpaper service | Built-in, no separate daemon |
| showoff (sleep screen) | Noctalia lock screen + idle | Built-in session lock + idle behavior |
| theme.nix (496-line custom engine) | Noctalia theming | Palette, app theming, templates — declarative via Nix HM module |
| GTK CSS generation (sync-ghostty) | Noctalia app theming | GTK + Qt templates replace hand-rolled CSS |
| hyprland.nix keybinds (371 lines) | Partially Noctalia IPC | Some keybinds become Noctalia IPC calls; window management stays Hyprland |
| way-edges (side-panel hub) | Noctalia dock + control center | Built-in dock, panels, widgets replace separate way-edges daemon |
| Notifications (if any) | Noctalia notifications | Built-in notification toasts + history |
| Clipboard (clipse) | Noctalia clipboard history | Built-in clipboard widget |

**What stays unchanged:**
- Hyprland itself (Noctalia is the shell *around* it)
- All dev tools: nvim, tmux, yazi, git, opencode, fastfetch
- System services: battery (TLP), network, audio, security, hardware
- Research toolchain: obsidian, zotero, pandoc/texlive
- Otter-launcher (user preference)
- Sandbox module

### 2.2 Foot Terminal

**What it is:** Fast, lightweight, Wayland-native terminal emulator. Designed
specifically for Wayland from the start (not a port from X11).

**Key features:**
- Server/daemon mode — instant window spawning (fork from running instance)
- Sixel image support (fastfetch logos, yazi previews)
- Scrollback search (Ctrl+Shift+R)
- URL detection with configurable styles
- On-the-fly font resize + DPI adjustment
- Shell integration (cwd tracking, prompt jumping, last-command piping)
- Theme support via INI files with `[colors-dark]` sections
- Unicode 17 support
- DE agnostic — designed for tiling WMs that open/close instances often

**Why foot over ghostty for the Noctalia host:**
- Ghostty's theme integration (sync-ghostty generating `theme.conf`) becomes
  void when Noctalia manages theming — Noctalia's palette engine handles app
  colors
- Foot's INI theme files can be generated by Noctalia's template system
- Foot's server mode is optimized for the tiling WM use case (fast spawn)
- Lighter weight — C, no GPU acceleration overhead
- No Helium browser dependency (ghostty is built on Zig/libghostty)

**Theme integration:** Noctalia has a community template for terminal sequences
(`docs.noctalia.dev/noctalia/templates/community/terminal-templates/`). This
can generate foot theme files from the Noctalia palette, replacing the
sync-ghostty GTK CSS pipeline entirely.

**Home Manager integration:** `programs.foot` is a first-class HM module with
full option support (settings, themes, server mode config).

### 2.3 Hyprland 0.55 + Lua Config

**Critical finding:** Hyprland 0.55 (nixpkgs 26.05) introduced Lua
configuration. The old `hyprland.conf` format is deprecated and will be removed
in a future release. Home Manager's `wayland.windowManager.hyprland.settings`
generates `hyprland.conf` (compatibility mode works for now but is deprecated).

**Noctalia autostart:** `exec-once = "noctalia"` via HM settings (works in
compat mode). The recommended approach is starting from the compositor, not
systemd.

**UWSM status:** Also reportedly deprecated in 0.55. The current config has
`withUWSM = false` already, so this is a non-issue.

## 3. Three-Host Architecture

### 3.1 Host Definitions

| Host | File | Purpose | Display Stack |
|---|---|---|---|
| **laptop** | `hosts/laptop.nix` | Current experimental/custom setup | Hand-rolled Hyprland + all current components |
| **workstation** | `hosts/workstation.nix` | Stable Noctalia desktop | Hyprland + Noctalia Shell + foot |
| **server** | `hosts/server.nix` | Headless NixOS server | No display |

All three run on the same T480 hardware (shared `nixos.hardwareConfig`).

### 3.2 Host Flags

The existing flag system (`custom.flags`) extends naturally:

```nix
# laptop.nix — experimental, full custom
custom.flags = {
  isDesktop = true;
  isLaptop = true;
  isExperimental = true;  # new flag
};

# workstation.nix — stable, Noctalia-based
custom.flags = {
  isDesktop = true;
  isLaptop = true;  # same hardware
  isNoctalia = true;  # new flag — Noctalia shell active
};

# server.nix — headless
custom.flags = {
  isServer = true;
};
```

Modules can branch on `isNoctalia` to skip components that Noctalia replaces.

### 3.3 The `desktop` Group Split

The current `homeManager.desktop` group imports everything. For the Noctalia
host, most of these become unnecessary:

**Current desktop group imports:**
```
hyprland, ghostty, tui, otterLauncher, showoff, awww, waypaper, waybar, theme
```

**Laptop host (experimental) keeps:** all of the above (unchanged)

**Workstation host (Noctalia) replaces:**

| Current Import | Noctalia Host Action |
|---|---|
| `hyprland` | Keep (compositor config, but simplify keybinds) |
| `ghostty` | **Remove** — replaced by foot |
| `tui` | Keep (icons provisioned for other apps) |
| `otterLauncher` | Keep (user preference) |
| `showoff` | **Remove** — Noctalia lock screen replaces |
| `awww` | **Remove** — Noctalia wallpaper service replaces |
| `waypaper` | **Remove** — Noctalia wallpaper picker replaces |
| `waybar` | **Remove** — Noctalia bar replaces |
| `theme` | **Remove** — Noctalia theming replaces |

**New Noctalia-specific imports needed:**
- `noctalia` — the Noctalia package + HM module
- `foot` — foot terminal (new module or HM `programs.foot`)

### 3.4 New Group: `noctaliaDesktop`

Create a new aspect group for the Noctalia desktop host:

```nix
# groups/noctalia-desktop.nix
{ self, ... }: {
  flake.modules.homeManager.noctaliaDesktop = {
    imports = [
      self.modules.homeManager.hyprland  # compositor config (simplified)
      self.modules.homeManager.noctalia  # Noctalia shell (new module)
      self.modules.homeManager.foot      # foot terminal (new module)
      self.modules.homeManager.tui       # icon provisioning
      self.modules.homeManager.otterLauncher  # user preference
    ];
  };
}
```

## 6. Foot Terminal Module

### 6.1 HM Module Approach

Home Manager has `programs.foot` with full option support:

```nix
programs.foot = {
  enable = true;
  settings = {
    main = {
      term = "xterm-256color";
      font = "JetBrains Mono:size=12";
      pad = "12x12";
      dpi-aware = "yes";
      server = "yes";  # daemon mode for instant spawning
    };
    scrollback = {
      lines = "10000";
    };
    cursor = {
      style = "beam";
      blink = "yes";
    };
    colors = {
      # Generated by Noctalia template or static theme
      foreground = "cad3f5";
      background = "24273a";
      regular0 = "1e2030";  # black
      regular1 = "ed8796";  # red
      # ... full 16-color palette
    };
  };
};
```

### 6.2 Theme Pipeline

Noctalia's template system can generate foot theme files from the palette.
The flow:

1. Noctalia generates palette from wallpaper (via matugen or built-in)
2. Noctalia template writes `~/.config/foot/themes/noctalia.ini`
3. Foot config includes: `include=~/.config/foot/themes/noctalia.ini`

Alternatively, foot themes can be static INI files shipped via Nix, updated
when the user changes the Noctalia theme.

## 7. Risk Assessment

| Risk | Severity | Mitigation |
|---|---|---|
| **Noctalia v5 is Beta** | Medium | laptop host preserves the full experimental setup as fallback. Can switch back by changing which host is deployed. |
| **Hyprland Lua config deprecation** | Low | Noctalia autostart works via `exec-once` in compatibility mode. Monitor HM issue tracker for Lua support. |
| **Noctalia + otter-launcher conflict** | Low | Both can coexist. Noctalia's launcher is a panel widget; otter is a separate app. User may eventually prefer Noctalia's launcher. |
| **Foot lacks some ghostty features** | Low | Foot has Sixel, scrollback search, server mode. Missing: GPU rendering, ligature rendering may differ. Test with user's font. |
| **Theme engine replacement** | Medium | Noctalia's theming is different from the custom sync-ghostty engine. May need iteration to get palette generation working for foot + GTK + apps. |
| **Cachix cache misses** | Low | Use `cachix` branch pin or accept build times. |

## 8. Migration Order

### Phase 0: Preparation (non-breaking)
1. Create `hosts/laptop.nix` as a copy of current `workstation.nix`
2. Verify `nix build` succeeds for both hosts
3. Add Noctalia flake input to `flake.nix`
4. Create `display/foot.nix` module (HM foot config)
5. Create `display/noctalia.nix` module (HM Noctalia config)
6. Create `groups/noctalia-desktop.nix` group

### Phase 1: Noctalia Host (non-breaking)
1. Rewrite `hosts/workstation.nix` to use Noctalia desktop group
2. Configure Noctalia: theme, bar widgets, wallpaper, keybinds
3. Configure foot as default terminal
4. Keep otter-launcher
5. Simplify hyprland.nix for Noctalia (remove showoff/awww autostart)
6. Build + test on a VM or second boot entry

### Phase 2: Cleanup (breaking for laptop)
1. Verify laptop.nix still builds with full original config
2. Update TODO.md with migration status
3. Update module-contracts.md with new host definitions
4. Update AGENTS.md with the 3-host architecture

### Phase 3: Refinement (iterative)
1. Tune Noctalia bar widgets to match waybar functionality
2. Set up Noctalia theme pipeline for foot + GTK apps
3. Migrate hyprland keybinds to Noctalia IPC where appropriate
4. Evaluate whether otter-launcher is still needed vs Noctalia launcher
5. Document the Noctalia configuration in user/maintenance.md

## 9. Open Questions

1. **Noctalia v5 Beta stability:** How stable is it for daily use? The CachyOS
   integration (June 2026) suggests production readiness, but it's still
   labeled Beta. Worth testing before committing.

2. **Hyprland Lua config:** The current HM module generates `hyprland.conf`.
   Noctalia's docs show Lua config (`hyprland.lua`). Will the HM module
   generate Lua in time, or do we need to manage the config file manually?

3. **Theme pipeline complexity:** The current sync-ghostty engine generates
   palette files for 7+ apps (ghostty, hyprland, waybar, tmux, nvim, cava,
   gtk). Noctalia's template system covers GTK + Qt + some community templates.
   How much of the per-app theming do we lose or need to rebuild?

4. **showoff replacement:** Noctalia has a lock screen and idle service, but
   showoff is a "magic workspace sleep screen" with tty-clock, cmatrix, etc.
   Is this a must-have feature, or is the standard lock screen sufficient?

5. **wayedges → Noctalia:** `way-edges` is a side-panel/hub widget system
   (Rust, wlr-layer-shell) that renders hidden widgets on screen edges — pop-out
   panels that can be pinned. Noctalia provides the same concept natively: dock,
   control center, panels, and widgets are all built into the shell. Noctalia's
   dock + launcher + control center effectively replace the need for way-edges
   as a separate daemon. The user's "wayedges system managing concept" is
   exactly what Noctalia consolidates.

6. **Performance on T480:** Noctalia is OpenGL ES based. The T480 has Intel
   UHD 620 — verify GPU acceleration works and the shell is responsive.

7. **Ghostty theme engine value:** If the workstation host drops ghostty entirely
   (no sync-ghostty, no theme.conf generation), the entire theme.nix custom
   engine becomes laptop-only. Is that the right long-term direction?
